> 状态:**草案(2026-07-13),待用户授权实现**

---

## 一、为什么做

README「已知限制」写着:**"AI Inspector 当前为纯状态展示,外接 LLM 接口预留在 v3"**。
`src/inspector.rs` 已经把 hook 铺好了——`Inspector` trait + `StubInspector`,注释明确:

> 外接模型:LLM API / MCP server 出来的结果,MoXin 不自训、不内置模型,
> 只负责提供结构化状态 + 渲染外部模型回答。(`cli-vision.md` §3)

现在四面板 TUI 的 AI Inspector 面板只渲染派生数据(电压/GPIO13/Loop Time/Sensors)。
这一步把它接上真模型:把 `RunState` 全外设快照喂给 LLM,让模型**解释当前 MCU 在干什么、
有没有异常**,把回答渲染进面板。这是 MoXin 名字("让 AI 读懂 MCU 仿真状态")的最后一块。

---

## 二、核心决策:shell-out 到 `curl`,守死依赖锁

MoXin 是**编排层**,一贯"自己不实现、shell-out 到外部运行时"(simavr / qemu /
arduino-cli / arm-gcc)。LLM 调用同理:**不引 `reqwest` / `ureq` 等 HTTP crate**,
而是 shell-out 到用户配置的命令(默认 `curl`),把请求体用 `serde_json` 拼、响应用
`serde_json` 解析。`curl` 成为又一个"按需的外部依赖",和 simavr 完全对等,
`moxin doctor` 一并自检。

| 决策 | 理由 |
|---|---|
| **shell-out curl,不引 HTTP crate** | 守 CLAUDE.md 依赖锁(不引新 crate);与项目"编排层 + 外部运行时"哲学一致;`curl` 几乎无处不在,缺了 doctor 会提示 |
| 请求/响应仅用 `serde_json` | 已在依赖里;body 拼装 + 响应解析都是纯函数,可单测 |
| API key 只从**环境变量**读,永不落盘/入库/进日志/进 prompt 之外 | 密钥安全;不进 moxin.toml(避免误提交);prompt 里只有硬件状态,无密钥 |
| LLM 调用在**后台线程**,TUI 读缓存 | LLM 秒级延迟,TUI 50ms 刷新;绝不阻塞渲染 |
| 失败**降级**到 StubInspector + 一行提示,永不崩 | curl 缺失 / 无 key / 网络错 → 回退纯派生视图,注明 "LLM offline: <reason>" |
| LLM **只读建议**,绝不驱动仿真 | 驱动仿真是 MCP(v3.0)的职责;Inspector 只解释状态,职责分离 |

### ❌ 不做

- 不引任何 HTTP / LLM SDK crate(reqwest / ureq / async-openai / anthropic-sdk 全不引)
- 不内置模型权重、不自训、不做本地推理
- 不让 LLM 通过 Inspector 反向驱动仿真(那是 MCP server 的事)
- 不把密钥写进 moxin.toml / 状态快照 / 日志
- 不改 bridge / SCHEMA_VERSION / LICENSE

## 三、配置(全走环境变量)

| 变量 | 默认 | 说明 |
|---|---|---|
| `MOXIN_LLM_CMD` | (内置 curl 模板) | 覆盖整条调用命令;`{url}` 占位,body 走 stdin |
| `MOXIN_LLM_URL` | `https://api.anthropic.com/v1/messages` | 端点 |
| `MOXIN_LLM_MODEL` | `claude-haiku-4-5` | 模型 id(低延迟优先) |
| `MOXIN_LLM_API_KEY` | (无) | 密钥;未设 → Inspector 走 stub + 提示 |
| `MOXIN_LLM_KEY_HEADER` | `x-api-key` | 便于切 OpenAI 兼容端点(`Authorization: Bearer`) |

内置 curl 模板(示意,Anthropic Messages API):

```
curl -sS --max-time 20 {url} \
  -H "content-type: application/json" \
  -H "x-api-key: $MOXIN_LLM_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  --data @-        # body 从 stdin,避免密钥/大 payload 进进程参数
```

密钥经 `-H` 拼进 header;为不进 argv(`ps` 可见),后续可用 `--config -` 从 stdin 传
header(实现细节留 M1 定,原则:**密钥不进 argv**)。

## 四、结构(复用现有 hook)

```rust
// src/inspector.rs —— 现有 trait,新增实现,StubInspector 保留
pub struct LlmInspector { /* 配置 + Arc<Mutex<Option<LlmAnswer>>> 缓存 */ }
impl Inspector for LlmInspector { fn inspect(..) -> (lines, status) { 读缓存 } }

// 纯函数(可单测,无网络)
fn build_prompt(project: &Project, state: &RunState) -> String   // 拼硬件状态 + 提问
fn build_request_body(model, prompt) -> serde_json::Value        // Messages API body
fn parse_answer(resp: &str) -> Result<String>                    // 抽 content[0].text

// shell-out(带 curl 探针,缺则降级)
fn call_llm(cmd, url, body) -> Result<String>                    // Command::new(curl)...
```

后台 worker:每 N 秒(或 TUI 里按键触发)快照 `RunState` → `build_prompt` →
`call_llm` → `parse_answer` → 写缓存;`inspect()` 每帧读缓存渲染。失败写降级提示。

新增 `moxin explain`(一次性 CLI,非 TUI):读最近 `.moxin-state.json` →
`build_prompt` → `call_llm` → 打印模型分析。给 CI / 脚本 / 无 TUI 环境用,也是
纯 shell-out 的最小可测路径。

## 五、测试策略

- `build_prompt` / `build_request_body` / `parse_answer` 全纯函数 → 纯单测
  (喂假 RunState 断言 prompt 含 "GPIO13"、假响应 JSON 断言抽出 text、坏 JSON 报错)
- `call_llm` 带 `curl --version` 探针,缺 curl `return`(同 simavr 测试约定)
- CI 可选加一道"假端点"关卡:本地起个回声脚本冒充 LLM,验证 shell-out 闭环
  (不打真 API,不进真密钥;或直接跳过留本地验证)
- 目标:M1 收尾纯函数单测覆盖 build/parse;`cargo test` 不因缺 curl/key 挂

## 七、安全与隐私

- 密钥只从 env 读,**不进** argv / moxin.toml / `.moxin-state.json` / bridge 日志 / commit
- prompt 内容只有**硬件仿真状态**(引脚/传感器/串口尾),无用户密钥、无源码外泄
- 出站请求经用户自己的 `curl` + 用户自己的端点/密钥;MoXin 不代理、不缓存响应到盘
- 默认**不启用**:未设 `MOXIN_LLM_API_KEY` 时 Inspector 行为与今天完全一致(纯 stub)
