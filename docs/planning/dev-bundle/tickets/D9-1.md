# D9-1 · 写 demo 用的"故意有 bug 的 firmware"

预计工时：1 小时
模块：docs/demo

---

## 任务

为 D9-2 的录视频准备一段**故意写错**的 firmware，让 Cursor / Claude Code 通过
MoXin 工具链自己发现并修复。Bug 要满足三个条件：

1. **现实可信**：是新手会犯的真实错误，不是凭空捏造
2. **看代码看不出**：必须靠 MoXin 工具链才能定位（凸显 MoXin 价值）
3. **修复简单**：30 秒内能改对（视频不能太长）

## 验收

`docs/demo/buggy-blink/` 目录，包含：
- `moxin.toml`：LED on D13
- `src/main.ino`：故意有 bug 的代码
- `BUG.md`：bug 说明（演员剧本，视频拍摄时用，最终不发布）

bug 用 `moxin run --output json | head -50` 能看出来，但单看 .ino 源码不容易发现。

## Bug 备选（任选一）

### 备选 A：delay 单位错（推荐）

```cpp
// 用户期望 LED 每秒闪 1 次（1Hz）
// 但 delay 接受的是毫秒，新手以为是秒，写成 delay(1)
void setup() { pinMode(13, OUTPUT); }

void loop() {
    digitalWrite(13, HIGH);
    delay(1);     // ❌ 应该是 1000
    digitalWrite(13, LOW);
    delay(1);     // ❌ 应该是 1000
}
```

**MoXin 工具链如何发现**：跑 `moxin run --output json | head -50`，会看到 pin 事件
`t_us` 间隔约 1000us（1ms）而不是 1_000_000us（1s）。AI 看到这个时间差立刻识别出
delay 单位用错。

### 备选 B：pinMode 写漏

```cpp
void setup() {
    // ❌ 漏写 pinMode(13, OUTPUT);
    // Arduino 默认所有 pin 是 INPUT，digitalWrite 后引脚激活上拉电阻
    // LED 会很暗但看代码完全正常
}

void loop() {
    digitalWrite(13, HIGH);
    delay(1000);
    digitalWrite(13, LOW);
    delay(1000);
}
```

**MoXin 工具链如何发现**：`moxin status --pin D13` 会显示 LOW（因为内部上拉
不足以让 LED 真亮）。AI 跑 status 发现 pin 一直 LOW，回去看代码意识到 pinMode 缺失。

### 备选 C：buzzer 频率写错

```cpp
// 用户想用 buzzer 播放 440Hz 的 A 音，但写成了 4400Hz（多了个 0）
void setup() {
    pinMode(8, OUTPUT);
}
void loop() {
    tone(8, 4400);  // ❌ 应该是 440
    delay(1000);
    noTone(8);
    delay(500);
}
```

**MoXin 工具链如何发现**：`moxin assert "buzzer buzz1 frequency 440 within 2s"`
失败，且 `moxin status` 显示 frequency 4400。AI 立刻看出多了个 0。

**推荐用备选 A**——最直观，时间差视觉证据最强。

## BUG.md 演员剧本

```markdown
# 视频脚本（不发布）

## 场景设置
打开 Cursor，open buggy-blink/ 项目。

## 用户提问（按 D9-1 备选 A 备选 B）
"This blink demo isn't working — the LED is supposed to blink once a second
but I can't see it changing. Help me debug."

## AI 期望行为
1. AI 读 src/main.ino，看起来正常（不会立刻发现 1ms vs 1000ms 的笔误）
2. AI 跑 `moxin run --output json > /tmp/moxin.log 2>&1 &`
3. AI 跑 `tail /tmp/moxin.log` 看 JSON 流
4. AI 注意到 pin 事件 t_us 间隔约 1000，而不是 1_000_000
5. AI 回去看 main.ino，意识到 delay(1) 应该是 delay(1000)
6. AI 改 .ino 文件
7. AI 重新跑 sim，验证 t_us 间隔变成 1_000_000

## 录制要点
- 全程不演用户手动干预 AI
- AI 一次给出最终答案的话，剪掉中间思考过程
- 视频字幕标注 "AI 通过 MoXin JSON 流定位 bug，不靠看代码"
```

## 约束

- ❌ bug 不能是"语法错误"那种 IDE 一秒报红的
- ❌ bug 不能太隐蔽（视频要能 3-5 分钟讲完）
- ✅ buggy firmware 必须能**编译通过**，仅运行时表现不对
