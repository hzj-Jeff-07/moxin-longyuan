# D1-4 · STM32 wire 命令统一改用 PA13，删 D13 别名误导

预计工时：45 分钟
模块：boards / examples / docs

---

## 任务

STM32 上 `wire pin13 -> led1.a` 现在会报错，因为 `stm32f405.rs` 里 PinSpec 只有
`PA0..PC15`，没有 `D13` 别名。但 README 暗示这条命令能用，example toml 里又写了
`from = "board.D13"` —— 三方不一致。

策略：**对外承认 STM32 用 ARM 风格的 PAn 命名**，删 Arduino 风格的别名误导。这是
更诚实的做法，"D13" 本来就是 Arduino 包装出来的概念。

## 验收命令

```bash
cd moxin-longyuan
cargo test                # 全绿
moxin new test-stm32 --board=stm32
cd test-stm32
cat moxin.toml | grep "from = \"board.PA13\""   # 模板里用 PA13
moxin run                  # 跑通 STM32 blink
# 进 TUI 后输入：wire PA12 -> led1.anode 应能成功；wire D12 应明确报错
```

## 涉及的文件（4 个）

### 1. `examples/stm32-blink/moxin.toml`

把 `from = "board.D13"` 改成 `from = "board.PA13"`。

### 2. `src/boards/stm32f405.rs` 中的 `scaffold_project`

cmd_new 生成的默认 moxin.toml 里 wire 用 PA13。检查现有代码：

```rust
fn scaffold_project(&self, name: &str) -> Project {
    Project {
        project: ProjectMeta { name: name.into(), board: "stm32".into(), ... },
        components: vec![
            Component { id: "led1".into(), r#type: "led".into(), color: Some("red".into()), .. }
        ],
        wires: vec![
            Wire {
                from: "board.PA13".into(),    // 确认这里是 PA13 不是 D13
                to: "led1.anode".into(),
            }
        ],
    }
}
```

### 3. `src/boards/stm32f405.rs` 中的 `source_template`

默认 firmware C 代码 GPIOA pin 13 切换，已存在，**不动**。验证 pin 编号匹配。

### 4. `README.md`

如果 README 在 STM32 章节里出现 `wire D13` 之类的示例，改成 `wire PA13`。
同时在 STM32 章节加一行注释：

> **关于引脚命名**：STM32 项目使用原生的 `PA0`–`PC15` 命名，不使用 Arduino 风格的
> `D0`–`D13`。若需 Arduino 兼容引脚映射，Phase 2 可能加入。

## 修改前后对比

**`examples/stm32-blink/moxin.toml`** —— before：

```toml
[[wire]]
from = "board.D13"      # ❌
to = "led1.anode"
```

after：

```toml
[[wire]]
from = "board.PA13"     # ✅
to = "led1.anode"
```

## 约束

- ❌ 不要给 STM32 spec 加 D0-D13 别名（那是 Phase 2 的 Arduino 兼容层方案）
- ❌ 不要改 STM32 firmware C 模板（pin 13 in GPIOA 是物理映射）
- ❌ 不要改 Arduino Uno 的 D13 处理（那里 D13 是合法的）
- ✅ 改 4 个文件：moxin.toml example + boards/stm32f405.rs scaffold + README + 任何其他出现 STM32 `wire D` 的地方

## 同时验证

`moxin shell` 里执行：
- `wire PA13 -> led1.anode` ✅
- `wire pin13 -> led1.anode` ❌ 应报错 "unknown pin D13 on stm32"（这个错原本就有）
- `wire D13 -> led1.anode` ❌ 同上
