## Issue 模板

每个 issue 用统一模板：

```markdown
**类型**：[功能 / 元件 / 板 / 重构 / 文档 / CI]
**优先级**：[p0 / p1 / p2]
**依赖**：[列出依赖的其他 issue 编号]

## 背景
[为什么 Phase 1 没做，为什么 Phase 2 要做]

## 验收标准
- [ ] 具体可执行的检验命令 1
- [ ] 具体可执行的检验命令 2

## 实现要点
[给将来 ticket 化的提示]

## 不要做的
[scope 边界]
```

例如 issue #5 DHT11：

```markdown
**类型**：元件
**优先级**：p0
**依赖**：#23 (bridge 协议加 version 字段)

## 背景
DHT11 是教学场景最常用的环境传感器（温湿度）。Phase 1 没做是因为：
- 需要单总线协议时序仿真
- 需要"用户手动注入温湿度环境量"的机制

## 验收标准
- [ ] `moxin add dht11 sensor1` 不报错
- [ ] `wire D2 -> sensor1.data` 成功
- [ ] TUI 加快捷键 `t` / `T` 调温度，`h` / `H` 调湿度
- [ ] firmware 跑 `DHT.read()` 返回 moxin 注入的值

## 实现要点
- 单总线时序：~40us bit periods，模拟主机请求后从机 80us low + 80us high 应答
- bridge 端实现 DHT11 状态机
- 协议入向命令：`set-env sensor1 temp 25.0 humidity 60`

## 不要做的
- 不做 DHT22（精度更高的版本，等用户呼声）
```
