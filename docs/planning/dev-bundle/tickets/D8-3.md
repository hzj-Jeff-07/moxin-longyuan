### docs/ai-templates/cursorrules.template

```
# Cursor rules for MoXin embedded projects

You are working on a MoXin embedded project. MoXin is a CLI hardware simulator.

## Key commands
- `moxin run --output json`     starts simulation, emits JSON Lines to stdout
- `moxin status --pin D13`       queries current pin state of running sim
- `moxin status --serial-tail`   reads recent serial output
- `moxin assert "<expr>"`        asserts sim state, exit 0=PASS / 1=FAIL

## Workflow when user reports a bug

1. Read `src/main.ino` or `src/main.c` first
2. Read `moxin.toml` to understand the wiring
3. Start sim with `moxin run --output json > /tmp/moxin.log &`
4. Use `moxin assert` to write a failing test that captures the bug
5. Modify firmware to make the assert pass
6. Verify with another `moxin assert`

## Don't
- Don't modify Rust code in MoXin itself unless asked
- Don't change moxin.toml schema (it follows docs/component-schema.md)
- Don't add new dependencies to Cargo.toml of user project (it's a firmware project)

## Schema
- moxin.toml uses [project] / [[component]] / [[wire]] sections
- See docs/component-schema.md in MoXin repo for component types and pin names
```

### docs/ai-templates/CLAUDE.md.template

```markdown
# CLAUDE.md

This is a MoXin embedded project. MoXin is a CLI hardware simulator that
exposes simulation state via JSON Lines + a status query API.

## Tools you have

| Command | Purpose |
|---|---|
| `moxin run --output json` | Compile firmware, start sim, stream events |
| `moxin status --all` | Query latest sim snapshot (JSON) |
| `moxin status --pin <name>` | Query specific pin state |
| `moxin assert "<expr>"` | Wait for a condition, exit 0=PASS or 1=FAIL |

## Assert DSL examples

\`\`\`
moxin assert "pin D13 HIGH within 2s"
moxin assert "serial contains \"ready\" within 1s"
moxin assert "led led1 on within 500ms"
moxin assert "buzzer buzz1 frequency 440 within 3s"
\`\`\`

## When debugging

1. Read firmware source and moxin.toml
2. Run `moxin run --output json > /tmp/log &`
3. Write a failing assert that captures the reported bug
4. Fix the firmware
5. Verify assert passes
6. Kill the sim before moving on

## Project structure

- `src/` — firmware sources (.ino or .c)
- `moxin.toml` — components and wiring
- `bridge/` — DO NOT EDIT (those are simulator internals)

## Forbidden

- Editing MoXin source (Rust code outside this project)
- Adding production dependencies to Cargo.toml
- Modifying bridge/* C code
```
